**git-commit-helper** is an open-source Agent Skill and deterministic toolkit that turns AI coding assistants into an intelligent, disciplined, and safe Git Workflow Partner.

---

## Overview

When AI agents work on codebases, committing changes is one of the highest-friction and highest-risk operations:
- Agents often run `git add .` blindly, staging sensitive credentials or temporary debug files.
- Commit messages generated by LLMs frequently lack consistent formatting, proper scopes, or conventional commit adherence.
- Large changes combining unrelated bug fixes and features are bundled into monolithic commits.
- Destructive commands like `git push --force` or automatic commits without user review can corrupt history or push broken code.

`git-commit-helper` solves this with a **Decoupled Architecture**:
1. **Deterministic Layer (Python Helper Scripts)**: Read-only CLI tools running standard library Python (zero third-party dependencies). They inspect git states, analyze diffs, detect and redact secrets, validate commit conventions, and extract history patterns.
2. **Cognitive Layer (AI Agent + SKILL.md + References)**: The AI coding agent handles semantic code comprehension, change grouping, commit message generation, interactive questioning, and asks for user confirmation.
3. **Safety Boundary**: Helper scripts have **zero** write/mutation operations on git. The agent executes commits **only after explicit user confirmation**.

## Python Helper Scripts

All scripts are standalone, executable via `python <script>.py`, and output structured JSON.

### 1. `git-status.py`
Inspects repository root, branch, HEAD, staging area, unstaged changes, untracked files, and in-flight operations (merge, rebase, cherry-pick, revert).

```bash
python skills/git-commit-helper/scripts/git-status.py [--repo-path /path/to/repo]
```

**Sample Output:**
```json
{
  "is_git_repository": true,
  "repo_root": "/path/to/repo",
  "branch": "feat/user-auth",
  "head": "a1b2c3d4e5f6...",
  "is_unborn": false,
  "in_progress_state": null,
  "upstream": "origin/feat/user-auth",
  "ahead": 1,
  "behind": 0,
  "staged": [
    { "path": "src/auth.py", "status": "modified" }
  ],
  "unstaged": [
    { "path": "tests/test_auth.py", "status": "modified" }
  ],
  "untracked": [
    "temp.log"
  ],
  "summary": {
    "staged_count": 1,
    "unstaged_count": 1,
    "untracked_count": 1
  }
}
```

### 2. `analyze-diff.py`
Parses staged or unstaged diffs with line limits, diff statistics, binary file identification, and automated secret redaction.

```bash
python skills/git-commit-helper/scripts/analyze-diff.py [--staged] [--max-diff-lines 500] [--repo-path /path/to/repo]
```

**Key Features:**
- Automatically redacts API keys, passwords, AWS tokens, and Slack/GitHub tokens with `[REDACTED_SECRET]`.
- Enforces line count limits to avoid blowing up LLM context windows.
- Computes addition and deletion statistics per file.

### 3. `validate-commit.py`
Validates commit messages against Conventional Commits v1.0.0.

```bash
python skills/git-commit-helper/scripts/validate-commit.py --message "feat(auth): add password hashing"
```

**Sample Output:**
```json
{
  "valid": true,
  "header": "feat(auth): add password hashing",
  "type": "feat",
  "scope": "auth",
  "description": "add password hashing",
  "is_breaking": false,
  "breaking_description": null,
  "body": null,
  "footers": [],
  "errors": [],
  "warnings": [],
  "suggestions": []
}
```

If the format is invalid (e.g. uppercase description, trailing period, or invalid type), it provides precise error messages and suggested fixes.

### 4. `summarize-history.py`
Analyzes recent commits to deduce repo-specific conventions, top commit types, and common scopes.

```bash
python skills/git-commit-helper/scripts/summarize-history.py [--limit 50] [--repo-path /path/to/repo]
```

## Agent Usage & Safety Boundary

When installed as an Agent Skill in an AI assistant (Antigravity, Claude, Cursor, Copilot, etc.):

1. The agent executes `git-status.py` to inspect modified files.
2. The agent runs `analyze-diff.py --staged` (or unstaged) to inspect changes.
3. If changes contain unrelated modifications, the agent suggests logical commit splitting.
4. The agent crafts a Conventional Commit message and validates it using `validate-commit.py`.
5. **Human-in-the-Loop Gate**: The agent presents the proposed commit message and list of files to the user and asks for explicit confirmation before staging or committing.
6. Forbidden actions:
   - NEVER run `git push` without explicit user request.
   - NEVER run `git commit --amend`, `git rebase`, or `git reset --hard` autonomously.
   - NEVER run `git add .` or stage sensitive files (`.env`, credentials, secrets).
